This page lists faults in Jig that you can run into without reading its source code. Each entry
says what you will see, what it can cost you, and what to do instead.

<Note>
  **What this page describes.** Jig as it stands today — the code the next release is cut from.
  It is not a report about one installed version, so your copy may behave differently.
  The [changelog](/changelog) is where each release records what changed.
</Note>

**This is not the page for "something went wrong".** If a command refused, a setting did not take,
or your agent ignored Jig, start with [Troubleshooting](/troubleshooting) — those are problems with
an answer today. An entry below stays here until the fault is actually fixed, and it is removed in
the same change that fixes it.

The page is not a list of everything Jig could do better, and it is not a copy of Jig's to-do list.
Work already under way is left out. For the order these are being fixed in, and what comes after
them, see [What's next](/roadmap).

{/* Closed by task released-source-local-edits. */}
### Local edits in a released Jig still count as the release

**What you see.** The Jig on your machine is at a release tag, but someone changed files in it
(`~/.local/share/jig`, or a clone at a tag). `jig upgrade` in a copy-mode project takes those files
and records the plain release number, and `jig status` calls the versions equal.

**What it costs.** The project carries framework files no release contains, under a release's
number, and the next person's `jig verify` asks them to upgrade to the same release.

**What to do instead.** Keep the global Jig clean: `git -C ~/.local/share/jig status --short`
should print nothing. `jig self-update` already refuses a checkout with changes.

{/* Closed by task installer-ref-main-project-setup. */}
### The Windows installer cannot set up a project from `-Ref main`

**What you see.** `install.ps1 -Ref main` (or any branch) installs Jig, offers to set up a project,
and then reports that `jig init` failed: the source is not a release.

**What it costs.** The project folder is not set up; nothing in it is changed.

**What to do instead.** Install without `-Ref` for a project you work in. To try unreleased Jig, run
`jig init --unreleased` in the project yourself.

{/* Closed by task writes-in-own-tree-findings (F30, F31). */}
### A rejected edit can come back through `jig spec item` or `jig writes ship`

**What you see.** A pull request of a write was closed without merging, and the spec's base has since
changed, to an open epic or back from a finished one: the next edit carries the rejected commit into a new pull request. `jig writes
ship` does the same to a branch origin has lost when the record names no pull request.

**What it costs.** At `agent.git: merge`, `jig writes ship` can merge what you rejected. At lower
levels a pull request shows it again, and you see it in the diff. A commit a person pushed to that
branch is carried with it.

**What to do instead.** Keep the level below `merge` until this is fixed. To drop a rejected edit, rename
the local branch and delete it on origin: `git branch -m <branch> <new-name>`, then `git push origin
--delete <branch>`. Renaming alone is not enough, as the commit comes back from origin.

{/* Closed by task writes-in-own-tree-findings (F32, F33). */}
### A write can refuse with `branch-has-other-commits` after a squash merge

**What you see.** After a squash merge whose branch was deleted on origin, a write can refuse with
`branch-has-other-commits` and say no write of Jig's made those commits, though what is on the branch has
already merged.

**What it costs.** Writes to that spec stop until the branch moves out of the way. No commit is
lost, but see below for an edit waiting on the branch you rename.

**What to do instead.** Rename the local branch, `git branch -m <branch> <new-name>`. The refusal
suggests a push, which would bring back on origin what you already merged. An edit waiting on that
branch then no longer shows in `jig writes` or `jig status`; its commit and pull request stay.

{/* Closed by task writes-in-own-tree-findings (F34). */}
### A write trusts a remote branch that was deleted, until you prune

**What you see.** When a branch or an epic was deleted on origin and this clone has not pruned it, a
write treats what that old ref held as being on origin, and may push it again.

**What it costs.** Commits from a branch deleted on origin go back to origin, on the write's branch.
Commits origin never had are not published this way.

**What to do instead.** Run `git fetch --prune` before writing after you delete a branch on origin.

{/* Closed by task writes-in-own-tree-findings (F35). */}
### `jig writes` keeps showing an edit `jig writes ship` refused as gone

**What you see.** `jig writes ship` answers `not-found` for an edit whose pull request closed or
landed, while `jig writes`, `jig status` and `waiting` in `jig spec list --json` still
count it.

**What it costs.** A number that stays one too high, until the next edit to that target.

**What to do instead.** Trust the answer of `jig writes ship`.

{/* Closed by task knowledge-json-findings (F6). */}
### One rare character turns every non-ASCII letter of a knowledge answer into `?`

**What you see.** When text in a knowledge JSON answer holds a character from U+100000 to U+10FFFF, in
a summary of `jig knowledge proposed --json` or in the file behind `sources --diff --json`, every
non-ASCII letter of the whole answer reads `?`, in the other documents too. The same happens to any non-ASCII text on a machine with no `iconv`.

**What it costs.** A program, such as Jig UI, shows summaries in Cyrillic or any other non-Latin
script as question marks. The JSON stays valid and nothing else is lost.

**What to do instead.** Read the text form, which prints the text as written, and remove the character
where it is yours to remove.

{/* Closed by task knowledge-json-findings (F3). */}
### Knowledge JSON names a different file for a path that is not UTF-8

**What you see.** In `jig knowledge sources --json` and `proposed --json`, a stub that links a file whose
name has a byte that is not UTF-8 reports the name with the byte removed: `docs/w<FF>.md` reads `docs/w.md`, with nothing in the answer to say so.

**What it costs.** A program can show, or open, a different file of that shorter name.

**What to do instead.** Give the linked file a UTF-8 name.

{/* Closed by task knowledge-json-findings (F4). */}
### A proposed stub has two states in `jig knowledge sources --json` and `--diff --json`

**What you see.** A stub not accepted yet reads `proposed` in `jig knowledge sources --json`, and
`unrecorded` in `jig knowledge sources --diff <id> --json`.

**What it costs.** A program that compares the two reads sees a state change that did not happen.

**What to do instead.** Take the state from `jig knowledge sources --json`.
