This page lists faults in Jig that you can run into without reading its source code. Each entry
says what you will see, what it can cost you, and what to do instead.

<Note>
  **What this page describes.** Jig as it stands today — the code the next release is cut from.
  It is not a report about one installed version, so your copy may behave differently.
  The [changelog](/changelog) is where each release records what changed.
</Note>

**This is not the page for "something went wrong".** If a command refused, a setting did not take,
or your agent ignored Jig, start with [Troubleshooting](/troubleshooting) — those are problems with
an answer today. An entry below stays here until the fault is actually fixed, and it is removed in
the same change that fixes it.

The page is not a list of everything Jig could do better, and it is not a copy of Jig's to-do list.
Work already under way is left out. For the order these are being fixed in, and what comes after
them, see [What's next](/roadmap).

## A pause request does not reach an agent working without autopilot

**What you see.** You ran `jig queue request <id> pause`, and the agent working on the task in an
ordinary session — not on autopilot — goes on from stage to stage. `jig status` shows the request
as pending under the task, and it stays pending. Only an autopilot run checks for the
request, when it enters its next stage; `jig context --task <id>` lists it, but an agent reads that
only when it asks for context.

**What it can cost you.** The work you wanted to stop goes on until you notice.

**What to do instead.** Tell the agent in its session to pause the task: `jig task pause <id>`
honours the request and takes it out of the queue. Or run the task on autopilot when you expect to
pause it from outside. Fixed by the task `pause-request-without-autopilot`.

## Two status page tests fail on a slow machine

This one concerns you only if you work on Jig itself.

**What you see.** `tests/status.t.sh` fails in
`test_status_page_shows_a_stopped_run_first_with_its_reason` or
`test_status_page_gathers_a_phases_stops_into_one_card`: the page reads `stopped 1 min ago` where
the test expects `stopped just now`. Both tests stop a run and then draw the page, and an age under
60 seconds is the only one that reads `just now`. When a loaded runner takes longer than that
between the two steps, the test fails.

**What it can cost you.** A red check on a pull request that changed nothing near the status page,
and a rerun.

**What to do instead.** Rerun the failed share. The tests pass when the machine is not loaded.
Fixed by the task `status-tests-age-flake`.

## You cannot approve a design yourself when your agent runs without questions

**What you see.** Your settings have `autopilot.unattended: true`, a T3 or T4 task has a new or
changed design, and no autopilot run is going on for it — the run ended, or you are taking the task
on by hand. `jig task gate <id> approved --by human` refuses, saying nobody answers for the task, and
`--by agent` refuses too, saying the gate is the human's. `jig status` and `jig status --json` still
show the design as waiting for your decision, while `jig task list --json` offers no `approve-gate`
action for it.

**What it can cost you.** A task stops at its gate with no command that records your approval.

**What to do instead.** Turn questions back on for one command and off again:
`jig config set --local autopilot.unattended false`, then
`jig task gate <id> approved --by human`, then `jig config set --local autopilot.unattended true`.
Fixed by the task `owner-gate-in-unattended-clone`.
